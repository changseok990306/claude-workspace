# 어도비 (`ads/`)

어도비 광고 계정을 운영하면서 **캠페인별 히스토리 · 소재 변경 일정 · 업무 체크리스트**를 관리하는 웹페이지예요.
서버나 설치가 필요 없고, `index.html` 하나로 열려요. 다크 모드를 지원해요 (우측 상단 스위치).

## 열어 보기

1. `ads/index.html` 파일을 **더블클릭** (크롬·엣지 등 브라우저로 열려요. 인터넷이 없어도 돼요)
2. 처음이라면 **“예시 데이터로 둘러보기”** 버튼을 눌러 보세요. 가짜 캠페인 3개가 들어가요.
   - 지우고 싶으면 “예시 ·”로 시작하는 캠페인을 삭제하거나 `데이터 → 모든 데이터 지우기`. (예시에는 소재 변경 일정 9개와 체크리스트 업무 9개도 들어 있어요)

## 화면 구성

위쪽 탭 3개 + 왼쪽 캠페인 목록이에요. 왼쪽에서 캠페인을 고르면 세 탭 모두 그 캠페인만 보여 줘요. (“전체”는 모두. 체크리스트의 **공통 업무**는 어느 캠페인을 골라도 항상 함께 보여요)
캠페인마다 색이 달라서 어디서든 구분돼요. 왼쪽 위 로고는 어도비 A 문양(`img/adobe-mark.svg`)이에요.

| 탭 | 하는 일 |
|---|---|
| **히스토리** | 캠페인별로 날짜와 메모를 남겨요. 날짜 최신순(위가 최신), 실시간 검색(내용·날짜·캠페인 이름), 삭제 |
| **소재일정** | **맨 위 캘린더**에 어도비 소재 변경 일정을 올려 두고 확인해요. 일정이 있는 날은 칸이 진하게 칠해지고 캠페인 색 칩이 붙어요. 아래에는 선택한 날짜의 일정과 전체 일정 목록(예정/지난 일정, 확인 완료 체크)이 있고, 그 밑에 광고 소재 점검 보드(준비/집행 중/종료 + 체크리스트)가 있어요 |
| **체크리스트** | 히스토리·소재 일정 말고 **그 밖의 업무**를 적고 날짜를 확인하며 체크해요. 매일(또는 평일) 하는 업무와 마감일까지 해야 하는 업무를 함께 관리하고, 맨 위에 **오늘의 진행률**이 나와요 |

## 소재일정 — 소재 변경 일정 캘린더

1. 왼쪽에서 **캠페인을 고르면** 캘린더와 목록에 그 캠페인의 일정만 나와요. (“전체”는 모두)
2. 달력의 **날짜를 누르면** 아래에 그날 일정이 나오고, 그 아래 **“이 날짜에 일정 추가”**에 날짜가 자동으로 들어가요. (두 번 누르면 바로 내용 입력칸으로 이동)
3. 일정은 **캠페인 · 날짜 · 종류 · 소재 변경 내용 · 메모**로 입력해요.

| 종류 | 달력 기호 |
|---|---|
| 소재 교체 | ↻ |
| 신규 오픈 | ＋ |
| 종료 | ■ |
| 점검 | ✓ |

- **일정이 있는 날은 다르게 보여요**: 칸 배경이 진해지고, 캠페인 색 칩(기호 + 내용)이 최대 2개 붙어요. 더 있으면 “+N건”. 좁은 화면(휴대폰)에서는 칩 대신 색 점으로 보여요.
- 오늘은 원으로, 선택한 날은 굵은 테두리로 표시돼요. 일요일은 빨강, 토요일은 파랑이에요.
- 각 일정 앞의 체크 칸으로 **확인 완료**를 표시하면 달력 칩이 흐려지고 목록에 취소선이 그어져요. 다시 누르면 되돌려요.
- 목록은 **오늘 이후(예정) / 지난 일정 / 전체**와 **확인 완료 / 미완료**로 거를 수 있고, 내용·메모·날짜(예: `11월 8일`)로 검색돼요. 남은 날은 `오늘`, `D-3`, `2일 지남`처럼 나와요.
- **키보드**: 날짜 칸에서 방향키로 이동(←→ 하루, ↑↓ 한 주), `Home`/`End` 그 주의 일요일/토요일, `PageUp`/`PageDown` 이전/다음 달.
- 일정은 **하루짜리**예요 (기간 일정 없음). 일정의 내용 수정은 없고 지우고 다시 추가해요.
- 일정과 체크리스트 업무는 백업(JSON)에 함께 저장돼요. (CSV 가져오기는 히스토리만 지원해요)

## 체크리스트 — 업무 관리

히스토리·소재 변경 일정에 해당하지 않는 **일반 업무**(리포트 확인, 정산, 권한 요청 등)를 적어 두고 날짜를 확인하며 진행하는 탭이에요.

**업무 종류** (“업무 추가”에서 고르면 필요한 날짜 칸만 나타나요)

| 종류 | 설명 |
|---|---|
| 매일 반복 | 시작일부터 매일 나타나요. 종료일은 선택. **날짜마다 따로 체크**해요 (오늘 체크해도 내일은 다시 체크 안 된 상태) |
| 평일만 반복 | 월~금요일에만 나타나요. 체크는 날짜마다 따로 |
| 기한 업무 | **마감일**까지 해야 하는 업무예요. 시작일(선택)을 넣으면 그 기간 동안 “오늘 할 일”에 나와요. 한 번 완료하면 끝 |
| 기한 없음 | 날짜 없이 쌓아 두는 업무 |

**화면 구성**
1. **맨 위: 날짜별 진행 상황** — 보고 있는 날짜(기본 오늘), `오늘 N건 중 M건 완료 (%)` 진행 막대, 지연·오늘 마감·7일 안 마감 건수 요약. `‹` `오늘` `›` 와 날짜 칸으로 다른 날의 업무와 체크를 볼 수 있어요.
2. **업무 추가/수정 폼** — 업무가 하나도 없으면 자동으로 펼쳐져요. 각 업무의 `수정` 버튼으로 이름·종류·날짜·캠페인·메모를 고칠 수 있고, **체크 기록은 그대로 유지**돼요.
3. **구간별 목록** (위에서부터)
   - **지연된 업무** — 마감이 지났는데 아직 안 끝낸 업무 (빨간 테두리, “2일 지연”)
   - **오늘 할 일** — 그날 해당하는 매일/평일 업무 + 오늘 마감 업무 + 기간 중인 업무 (“D-3”)
   - **예정된 업무** — 아직 시작 전이거나 마감이 먼 업무
   - **기한 없는 업무**
   - **완료한 업무** — 접혀 있고 눌러서 펼쳐요 (다시 체크 해제하면 원래 구간으로 돌아와요)
4. 검색(이름·메모), 업무마다 **캠페인 연결(선택)** — 연결하지 않으면 **공통 업무**예요.

**진행률 계산**: 그날 해야 하는 반복 업무 + 지연된 업무 + 오늘 마감/기간 중 업무 + 그날 완료한 업무 중 완료한 비율이에요. 마감이 먼 예정 업무와 기한 없는 업무는 포함하지 않아요.

**알아 둘 점**
- 반복 업무의 체크는 **날짜 기준**이라, 어제 못 한 것을 `‹`로 어제로 가서 체크하면 어제 기록으로 남아요.
- 한 번짜리(기한/기한 없음) 업무를 완료하면 **완료한 날짜가 오늘**로 기록돼요.
- 캠페인을 삭제하면 그 캠페인에 연결된 업무도 함께 삭제돼요 (공통 업무는 남아요).
- 사이드바 숫자는 그 캠페인에 연결된 업무 수예요 (공통 업무는 “전체”에만 합산).

## 데이터 넣기

**1) 직접 입력** — 각 탭의 입력 칸 (소재일정은 “＋ 소재 추가” 줄을 눌러 펼쳐요)

**2) 히스토리 CSV 업로드** — 우측 상단 `데이터 → 히스토리 CSV 가져오기`
- 파일을 고르면 **바로 반영하지 않고 미리보기**를 먼저 보여 줘요 (몇 행을 읽었는지, 문제가 있는 줄 번호와 이유, 새로 만들어질 캠페인).
- 문제가 있는 줄은 건너뛰고 나머지만 가져와요. 파일은 이 브라우저 안에서만 읽어요. 어디로도 올라가지 않아요.
- `양식 CSV 받기`로 빈 양식을 받아 채우면 편해요. 엑셀·구글 시트에서 “CSV(UTF-8)”로 저장하세요. (최대 2MB, 5000행)

| 필요한 열 (한글/영어 모두 가능) |
|---|
| **날짜**(date) · **캠페인**(campaign) · **내용**(content, memo) |

- 날짜는 `2026-11-08`, `2026/11/8`, `2026.11.08`, `20261108`, `2026년 11월 8일` 모두 읽어요.
- 파일에 없는 캠페인 이름은 **자동으로 새 캠페인으로 만들어요** (체크를 끄면 그 행은 건너뛰어요).
- 같은 파일을 두 번 가져오면 히스토리가 **중복으로 들어가요** (히스토리는 덮어쓰기가 없어요).
- `데이터 → 히스토리 내보내기`로 내보낸 파일은 그대로 다시 가져올 수 있어요. (엑셀 수식 실행을 막으려고 `=`로 시작하는 글 앞에 `'`가 붙지만, 다시 가져올 때 자동으로 떼요)

## 💾 데이터는 어디에 저장되나요?

화면 오른쪽 위에 **지금 저장 방식**이 표시돼요.

| 표시 | 의미 |
|---|---|
| **● 공유 저장소 연결됨** (초록) | 입력한 내용이 서버(Supabase)에 저장돼요. **어느 컴퓨터에서 열어도 같은 데이터**가 보이고, 다른 사람이 고친 내용도 자동으로 반영돼요. |
| 저장 중… | 서버와 맞추는 중이에요. |
| **연결 끊김 · N건 대기** (빨강) | 서버에 닿지 않아요. 입력은 **화면과 브라우저에 보관**되고, 연결되면 **자동으로 보내져요** (새로고침해도 남아 있어요). 창을 닫으려 하면 경고가 떠요. |
| 공유 저장소 연결 안 됨 (빨강) + 맨 위 안내 띠 | **설정이 잘못된 것**이에요. 안내 띠가 무엇이 빠졌는지 알려 줘요 → 아래 “문제 해결” 표. 이 동안 입력한 내용은 **이 브라우저에만** 저장돼요. |
| 이 브라우저에만 저장 (회색) | 서버가 없는 곳이에요 (`index.html`을 파일로 열었거나 서버 함수가 없는 호스팅). **다른 컴퓨터에서는 안 보여요.** |

**공유 방식 (서버 모드)**
- 데이터는 **항목 하나씩**(캠페인·히스토리·일정·업무·소재 각각) 저장돼요. 그래서 두 사람이 **서로 다른 것을 동시에 추가해도 둘 다 남아요.**
- 내 입력은 **바로 화면에 나타나고** 뒤에서 서버로 보내요. 다른 사람의 변경은 **20초마다, 창으로 돌아올 때, 인터넷이 다시 연결될 때** 받아 와요. (즉시가 아니라 최대 20초 늦을 수 있어요)
- **같은 항목을 동시에 고치면 나중에 저장된 쪽이 이겨요.** (예: 두 사람이 같은 업무 이름을 동시에 바꾸면 나중 것만 남음)
- **삭제는 지우지 않고 “삭제됨”으로 표시만** 해요. 실수로 지워도 Supabase **Table Editor → `ads_items` → 해당 행의 `deleted`를 `false`로** 바꾸면 되살아나요.
- 서버를 쓰기 전에 **이 브라우저에만 저장해 둔 예전 데이터는 서버로 옮기지 않아요.** (화면에 안 나오지만 브라우저에는 그대로 남아 있어요. 필요하면 백업 파일로 내보냈다가 `데이터 → 백업 불러오기`로 올릴 수 있어요)

**⚠️ 누구나 보고 고칠 수 있어요 (로그인 없음)**
- 주소를 아는 사람은 **누구나 보고, 추가하고, 지울 수 있어요.** 서버가 입력 형식·크기·횟수는 제한하지만 “누가” 쓰는지는 막지 않아요.
- 그래서 **고객명·금액 같은 민감한 정보는 적지 마세요.**
- 가끔 `데이터 → 백업 파일 받기`로 **사본을 받아 두세요.** (Supabase 무료 플랜은 자동 백업이 보장되지 않아요)
- “전체 삭제”와 “백업으로 바꾸기”는 **다른 사람 화면에도 똑같이 적용돼요.** 확인창에 그렇게 적혀 있어요.
- 나중에 “보기는 누구나, 고치기는 나만”으로 바꾸고 싶으면 로그인 기능을 붙이는 별도 작업이 필요해요.

## 이전에 있던 “성과 · 예산·일정” 탭

공개용 페이지에는 맞지 않아 **없앴어요.** 예전에 그 탭에 입력해 둔 데이터가 브라우저에 있었다면, 새 버전을 처음 열 때 **지워지기 전에 브라우저 안의 별도 칸(`ads-data-v1-removed`)에 한 번 복사해 둬요.** (화면에는 보이지 않아요. 필요하면 알려 주세요)
코드는 git 태그 `backup-ads-before-trim`에 그대로 남아 있어서 언제든 되살릴 수 있어요.

## 한도와 알려진 한계

- 캠페인 100개 · 히스토리 5000 · 소재 1000개 · 일정 2000개 · 업무 1000개. 브라우저 저장 공간(보통 5MB 안팎)이 먼저 찰 수도 있어요. 가득 차면 화면에 안내가 떠요.
- 히스토리·소재의 **내용 수정**은 없어요. (지우고 다시 쓰기. 소재는 상태 변경과 점검 항목 추가·삭제는 가능)
- 소재 점검 보드의 소재에는 날짜 칸이 없어요. 날짜가 있는 것은 위쪽 캘린더 일정으로 관리해요.
- 어도비 계정과 자동으로 연동되지는 않아요.

## 🚀 배포하기 (Vercel + Supabase)

세 가지를 하면 돼요: **① Supabase에 표 만들기 → ② Vercel 프로젝트 만들기 → ③ 환경변수 2개 넣고 배포**.
(포트폴리오 방명록에 쓰는 Supabase 프로젝트와 **같은 것**을 써도 돼요. 표 이름이 달라서 섞이지 않아요.)

### ① Supabase — SQL 한 번 실행
1. Supabase 대시보드 → 프로젝트 → 왼쪽 **SQL Editor → New query**
2. `ads/supabase/ads_items.sql` 파일 내용을 **통째로 붙여넣고 Run** (여러 번 실행해도 안전해요)
3. **Table Editor**에 `ads_items` 표가 생기면 성공이에요.

### ② Vercel — 프로젝트 만들기
1. [vercel.com](https://vercel.com) → **Add New… → Project** → GitHub의 `claude-workspace` 저장소 **Import**
2. **Root Directory → Edit → `ads`** 선택 ← **가장 중요해요.** 비워 두면 포트폴리오가 배포돼요. (이 저장소 맨 위의 `vercel.json`은 포트폴리오용이에요)
3. Framework Preset은 `Other`, Build Command·Output Directory는 **비워 둠**

### ③ 환경변수 2개 넣고 Deploy
**Environment Variables**에 아래 두 개를 넣어요 (이름이 정확해야 해요. 포트폴리오 방명록과 같은 이름이에요).

| 이름 | 값 (Supabase → Project Settings → API) |
|---|---|
| `SUPABASE_URL` | **Project URL** (`https://xxxx.supabase.co`) |
| `SUPABASE_ANON_KEY` | **anon public** 키 (⚠️ `service_role` 키는 절대 넣지 마세요) |

- 값은 이 저장소의 `.env.local`(내 컴퓨터에만 있는 파일)에도 있어요. 채팅이나 코드에는 붙여 넣지 마세요.
- **Deploy**를 누르고 `Ready`가 되면 주소로 접속해요. 이후 `main`에 push할 때마다 자동으로 다시 배포돼요.
- **환경변수를 나중에 넣거나 바꿨다면 반드시 Redeploy**(Deployments → ⋯ → Redeploy)해야 적용돼요.

### 접속해서 확인
오른쪽 위에 **“● 공유 저장소 연결됨”** 이 뜨면 성공이에요. 다른 컴퓨터에서 같은 주소를 열어 같은 데이터가 보이는지 확인해 보세요.

### 문제 해결 — 맨 위 안내 띠의 문구
| 안내 띠 | 해야 할 일 |
|---|---|
| “서버에 환경변수가 없어요: SUPABASE_URL, SUPABASE_ANON_KEY” | Vercel → 프로젝트 → Settings → Environment Variables에 그 이름으로 추가 → **Redeploy** (안내 띠에 적힌 이름만 추가하면 돼요) |
| “Supabase 키가 올바르지 않아요” | `SUPABASE_ANON_KEY`에 **anon public** 키를 넣었는지 확인 (service_role 아님, 앞뒤 공백 없이) → Redeploy |
| “ads_items 테이블이 없어요” | ① 단계의 SQL을 실행 (다른 Supabase 프로젝트에 실행했다면 `SUPABASE_URL`이 그 프로젝트인지 확인) |
| “Supabase에 연결할 수 없어요” | `SUPABASE_URL` 값이 맞는지(오타·`https://` 누락) 확인 |
| 표시가 “이 브라우저에만 저장” | 서버 함수가 없는 곳이에요. Root Directory가 `ads`인지 확인 (`ads/api` 폴더가 배포돼야 해요) |
| 포트폴리오가 열려요 | Root Directory가 `ads`가 아니에요 → Settings → General → Root Directory 수정 → Redeploy |
| Vercel 로그인 화면이 떠요 | Settings → **Deployment Protection**(Vercel Authentication)을 꺼야 다른 사람이 열 수 있어요 |

### 알아 둘 점
- 검색엔진에 안 잡히게 `noindex`가 들어 있어요 (`index.html`의 `<meta name="robots">`). 검색에 나오게 하려면 그 줄을 지우세요.
- 어도비 로고·이름을 공개 주소에서 쓰면 공식 사이트로 오해받을 수 있어요. “비공식 개인 페이지”라는 문구를 넣는 것을 권해요.
